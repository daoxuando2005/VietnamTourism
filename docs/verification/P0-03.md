# Bản ghi P0-03 — Hợp đồng API v1

Bổ sung: OpenAPI v1.1 và types đã sinh ở [P0-06](P0-06.md)/[P0-07](P0-07.md); [P0-09](P0-09.md) đối chiếu public/owner/bootstrap runtime và CI hosted đạt. Phần dưới là snapshot hợp đồng ban đầu.

- Ngày: 21/11/2026, Asia/Saigon.
- Yêu cầu: TECH-01/03, SEC-01, PROFILE-01 phần hợp đồng.
- Nguồn trước thay đổi: `ff76724`; mã và bằng chứng thuộc commit chứa bản ghi này.
- Trạng thái: **Hoàn thành phần hợp đồng ban đầu**; triển khai DB/JWT/FE và xác minh Supabase thật vẫn thuộc nhiệm vụ phụ thuộc.

## Đã thực hiện

1. Chốt [quy ước API](../api/CONVENTIONS.md): `/api/v1`, DTO công khai/riêng, UUID subject và ID text legacy, username/slug/alias, ngày/timestamp UTC, chi phí VND nguyên trong miền an toàn.
2. Chốt pagination 1-based/default 20/max 100, envelope danh sách, filter/sort whitelist/giới hạn từ khóa/parameter binding; chưa tạo endpoint danh sách giả để tính hoàn thành.
3. Chốt lỗi 400/401/403/404/405/409/413/429/500/503 và cấu trúc code/message/requestId/timestamp/errors; gateway tạo request ID, quy tắc log/timeout và không retry mutation.
4. Ma trận khách/thành viên/chủ sở hữu/admin/bị khóa/service; không tin metadata/header user ID, không trao admin quyền liên hệ mặc định. Quy định service identity, scope, batch tối đa 100 và không join DB chéo; chưa mở caller liên service chưa có xác thực.
5. Tạo [OpenAPI 3.0.3](../api/profile-v1.yaml) cho route public profile với response DTO/error/header rõ. Chỉ công bố route có code P0-04; private/bootstrap được ghi kế hoạch P0-06/07, không quảng bá như đã hoạt động.
6. Thêm `check:contract` bằng swagger-parser khóa 12.1.0 và vào CI; kiểm schema, tập trường công khai, security declaration. Có chế độ đối chiếu OpenAPI runtime và tên trường DTO.

## Kiểm tra và kết quả

- `npm run check:contract` → **Đạt** OpenAPI parser validation, `$ref` hợp lệ, public field boundary và public security declaration. [Log](evidence/P0-03-contract.txt).
- Quarkus HTTP test xác minh runtime có operation `getPublicProfile`; đối chiếu schema runtime bổ sung trong smoke P0-04.
- Kiểm hợp đồng không tự chứng minh JPA/JWT hay nghiệp vụ đã hoạt động.

## Chưa làm/chưa kiểm chứng

- Chưa sinh TypeScript client/types vào FE (P0-07); chưa có danh sách/filter/sort/mutation endpoint của các miền P1+.
- Chưa triển khai optimistic concurrency/idempotency/machine identity vì chưa mở luồng ghi/liên service; quy ước yêu cầu test khi thêm.
- Chưa kiểm chuyển ID/username của dữ liệu hosted do P0-02 chưa có owner inventory. Đã giữ ID legacy, nêu quy tắc xử lý username không đạt trước import.
- Chưa xác minh CI hosted trong bản ghi này. Chưa có contract compatibility diff với release trước vì đây là hợp đồng đầu tiên.

## Việc tiếp theo

P0-04 tạo khung theo hợp đồng, P0-05 schema thật và P0-06 JWT. Khi có thay đổi dữ liệu hosted ảnh hưởng hợp đồng, cập nhật spec/test theo quy tắc tương thích, không tự thay ID cũ.
